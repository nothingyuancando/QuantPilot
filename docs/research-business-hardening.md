# 研究业务隔离与多 Agent 验证

本轮将研究报告从全局数据改为项目数据，并把数据可信度、候选信号和投资风险分开。多 Agent 保留原有三路研究、风险交叉审查、结论汇总和单写入者结构，新增任务上下文、研究截止时点、证据检索和产物血缘校验。

## 项目隔离与迁移

研究 API 的 GET 查询和 POST 请求体均须提供 `projectId`。服务端先检查对应 capability 与项目成员角色，再把服务端解析的 `actorUserId` 和项目交给业务服务。默认关注列表和推送渠道使用项目独立 ID；报告、运行记录和推送记录均按项目读取和写入。发送前重新读取数据库中的报告、渠道和运行记录，拒绝跨项目、禁用渠道及错配的运行记录，并使用数据库中的报告正文。

迁移文件为 `prisma/migrations/20261031000100_scope_research_business_data/migration.sql`。它增加可空的项目字段与创建者字段，保留历史数据；无归属记录的 `project_id` 仍为 NULL，业务查询不会返回这些记录。项目删除后相关记录也回到隔离状态。这里采用应用层查询隔离，并未增加 PostgreSQL RLS。

上线前需按现有发布流程应用迁移，再发布依赖新字段的代码。本轮仅生成 Prisma Client 并验证 schema，未对业务数据库应用迁移。历史记录需要在核实归属后另行迁移；不能按首个用户或首个项目批量猜测归属。历史 v1 报告的评分也不能直接当作 v2 数据可信度。

## 研究口径

候选筛选先限制关注标的和市场，再排名取 Top N。进程、交易日和 Redis 缓存均包含筛选范围；报告组装还会再次检查标的、资产类型和截止日期。当前 A 股 screener 不支持 ETF 候选筛选，ETF-only 请求不会混入股票，报告会明确提示这一限制。

v2 报告将覆盖率和业务数据源可用性计算为数据可信度；候选分数单独表示信号强度。ClickHouse 服务健康不参与投资判断。缺少明确风险证据时标为“未评估”，不会由数据完整推导出低风险或买入建议。

研究任务在预取阶段固定研究时点并持久化到 run plan，同一任务复用该时点。未指定历史窗口的任务也会固定时点，因此采用截止日前的完整日线，而非持续变化的实时价。该限制只控制观察窗口，不能证明第三方数据在历史时点已经可得，也不能替代 point-in-time 数据库或交易日历。

## 多 Agent 约束

基本面、技术面和风险预检并行运行，交叉审查读取三路结果。汇总读取基本面、技术面、风险预检和交叉审查全部结果，保留来源产物 ID 与摘要。平台拒绝未知结论、无来源证据、擅自提高置信度、遗漏争议、遗漏未解决风险以及更改截止时点的结果。

各 specialist 接收原始研究问题、标的、数据需求和固定时点。只读检索工具仅访问本次输入产物，最多调用 3 次，最多 4 轮；查询和返回数量均有边界。检索保留同一记录的标的、日期和单位上下文。输入文件执行路径、大小和已登记摘要检查；输出通过契约与血缘校验后才写入。

模型输出的 `blocking` 本身不具有终止权限。风险策略区分建议限制与经过平台核验的拒绝/阻断；当前模型风险发现作为约束信息保留，确定性的时点与血缘违规会使该节点失败。这些检查验证引用关系，不证明模型结论在语义上正确。

## Benchmark 与复现

本轮验证完成后已按要求清理原始临时报告、截图、测试工作空间和对应数据库测试项目。下文报告文件名作为历史运行标识保留；原始文件不随源码提交，运行命令可以生成新的报告。

```bash
uv run --project services/market-data pytest services/market-data/tests/test_screener_safety.py -q
```

业务 benchmark 包含 50 个确定性案例，直接调用生产策略，覆盖可信度与风险分离、关注列表、跨项目及历史数据隔离、研究时点、汇总结论/风险血缘、检索上下文与评测配对。每个案例校验一次，再重复计时 20 次，输出 p50/p95 和 fixture 摘要到 `reports/evals/research-business-benchmark.json`。这些耗时是本地策略开销，不是模型或完整任务耗时；报告明确标记 `measuredModelQuality: false`。CI 增加同一命令。

后端另通过实际 screener 函数配合数据库和 Redis 测试替身，检查 PostgreSQL/ClickHouse 两条路径的先过滤后限额、不同关注列表缓存隔离和 ETF 空结果。它没有替代真实数据库集成测试。

单/多 Agent 比较只接受完整且一致的 E2E 配对：实验、用例、问题、完整输入和工具配置摘要、模型配置、评审版本、构建、重复次数、快照及 Skill 锁必须匹配。缺少信息时不展示效果差值。运行器接收 `QUANTPILOT_EVAL_EXPERIMENT_ID`、`QUANTPILOT_EVAL_FROZEN_INPUTS_SHA256`、`QUANTPILOT_EVAL_TOOL_CONFIG_SHA256`；这些值是实验方的声明，仍需实际捕获并回放同一份输入，不能随意填写来制造可比性。本轮未实现完整工具响应捕获/回放，也未测得真实模型的多 Agent 优势。

### 实际调用发现与修正

- CSS 追加超过 160 行上限后，模型重复提交同样输入：在工具 schema 与定制提示中明确行数、字符数和紧凑写法，保留原安全上限。
- 自定义 writer 完成编辑但在提交前耗尽 24k 非缓存输入预算：根据实际约 27k 的调用记录调整为 40k，保留 8 轮、12 次工具及累计准备输入上限。
- 专家初始 JSON 与一次修正共用输出预算，导致修正阶段 `max_tokens`：专家与汇总均设置 16k 累计输出预算，同时要求精简结论与解释，保留严格 schema、引用和风险血缘校验。所有失败尝试仍纳入用量。
- 通用修正提示把汇总的 `unresolvedRisks` 字段要求带入风险审查 schema：只向 synthesis 提供该字段要求，其他角色按各自 schema 修正。专家失败会保留底层错误码和信息，避免只记录 `ended with failed`。
- 评测器把同 requestId 的首个专家当 writer，并要求多 Agent 的全链路零 Token：改为按 acceptedSourceRunId 校验写入者，专家血缘与全链路用量另外核对，避免漏算专家成本。
- 部分模型案例实际请求标准模板：补上明确布局定制要求，确保真正走模型编辑与提交路径；标准渲染保留独立对照。
- 历史窗口请求复权与公告接口不支持：使用受支持的非复权历史日线；历史公告无数据时返回明确缺口，不能回退到未来数据。
- macOS 缺少 Linux 的 ss/proc 监听查询：增加 lsof 与工作目录归属检查，只停止本项目监听进程；预览提前退出时立即报告退出原因，超时附末尾日志。此前一次偶发预览失败未稳定复现，最新全量 contract 已通过。

市场输入使用本地合成 fixture（含明确历史可用时点），模型请求是真实 API 调用。这证明编排、调用与验收链路可执行，不代表实时行情源或投资判断准确率。未执行生产发布或数据库迁移。

### 单/多 Agent 实际观测与剩余门槛

完整多 Agent 运行 `report-1793449828055.json` 中四个业务案例均通过、工具失败为 0，但发布评测未通过：累计专家与 writer 用量超过每例 84k 非缓存输入阈值，组合案例累计 16 轮超过 12 轮阈值。该运行的产品对照曾被旧验收器误拒绝；修正后的验收器对同一原始证据重算通过，不能因此把整份失败报告改写为通过。

### 充值后续验（2026-10-31）

模型额度恢复后，真实 API 不再返回 402。首次续跑 `report-1793450720459.json` 为业务 3/4、产品对照 1/1：技术面汇总遗漏了上游“历史覆盖不完整”的风险说明，严格血缘检查正确拒绝；组合基本面专家还曾超过 3 次检索上限，后续节点重试成功，其失败用量仍计入总成本。

修正汇总提示，要求先逐条原样复制风险目录；校验反馈一次列出全部缺失风险，避免一次纠正后才发现下一项遗漏。没有放松风险校验或增加重试次数。新增回归测试覆盖多个遗漏项及完整保留的通过路径。技术面真实专项复测 `report-1793450707132.json` 通过，11 轮、68,578 个非缓存输入 Token。
